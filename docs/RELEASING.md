# راهنمای انتشار و مدیریت کلیدها (`docs/RELEASING.md`)

<div dir="rtl">

این سند رویهٔ رسمی انتشار نسخه‌های جدید **ژتون (`Zheton`)**، تأیید امضای دیجیتال فایل نصبی (`APK`) و چرخش کلید امضای نرخ‌های بازار (`ECDSA P-256`) را مشخص می‌کند.

---

## ۱. گواهی امضای دائمی اندروید (`APK Signing Certificate`)

از نسخهٔ `v1.2.0` به بعد، تمامی فایل‌های نصبی رسمی با یک کلید دائمی `RSA-4096` امضا می‌شوند تا به‌روزرسانی مستقیم روی نسخه‌های قبلی بدون حذف داده‌ها امکان‌پذیر باشد.

- **الگوریتم کلید:** `RSA 4096-bit` (`SHA384withRSA`)
- **شناسهٔ کلید (`Alias`):** `zheton`
- **اثرانگشت رسمی گواهی (`SHA-256 Fingerprint`):**
  ```text
  73:8A:13:45:B9:90:B0:11:BB:48:FD:5F:A7:05:DD:A7:C5:2D:3C:9E:6E:37:AD:7F:4A:89:39:AC:26:EA:FF:F0
  ```

### نحوهٔ بررسی اصالت `APK` توسط کاربر
پیش از نصب هر نسخه، می‌توانید اثرانگشت امضای دیجیتال فایل `APK` را با دستور زیر بررسی کنید:
```bash
apksigner verify --print-certs zheton-v1.2.0.apk
```
یا بررسی هش فایل با `SHA256SUMS` ضمیمه‌شده در صفحهٔ Release:
```bash
sha256sum -c SHA256SUMS
```

> [!IMPORTANT]
> نسخه‌های `v1.0.0`، `v1.1.0` و `v1.1.1` پیش از تعریف کلید دائمی منتشر شده بودند و دارای برچسب **Deprecated** هستند. برای ارتقا از آن نسخه‌ها به `v1.2.0`، یک بار نسخهٔ قدیمی را حذف و `v1.2.0` را نصب کنید؛ از نسخهٔ `v1.2.0` به بعد تمامی آپدیت‌ها بدون نیاز به حذف نصب خواهند شد.

### نگهداری پشتیبان کلید (`Keystore Backup`)
- فایل کلید اصلی و مشخصات آن در مسیر محلی امن (`~/.zheton-keys/`) نگهداری می‌شود و **هرگز** وارد مخزن گیت نمی‌شود.
- نگه‌داشتن حداقل **دو نسخهٔ پشتیبان آفلاین** از فایل `zheton-release.jks` و رمز آن در مدیر رمز عبور (`Password Manager`) الزامی است.

## ۲. کلید امضای دیجیتال نرخ‌های بازار (`ECDSA P-256`)

پایپ‌لاین نرخ‌ها (`rates-pipeline/`) خروجی `rates.json` را با کلید خصوصی `RATES_SIGNING_KEY` به روش `ECDSA P-256 (SHA-256, IEEE-P1363)` امضا کرده و امضا را در `rates.json.sig` منتشر می‌کند.

- **کلید عمومی فعلی (`kid: "k1"`):** در مسیر `rates-pipeline/keys/rates.pub.pem` قرار دارد و درون کد اندروید (`Data.kt`) و وب‌اپلیکیشن (`marketService.ts`) تعبیه شده است.

### رویهٔ چرخش کلید (`Key Rotation`)
کلاینت‌های اندروید و وب هم‌زمان تا **دو کلید عمومی** (`k1` و `k2`) را می‌پذیرند:
1. کلید جدید (`k2`) را تولید کنید:
   ```bash
   openssl ecparam -name prime256v1 -genkey -noout -out rates-private-k2.pem
   openssl ec -in rates-private-k2.pem -pubout -out rates-pipeline/keys/rates-k2.pub.pem
   ```
2. کلید عمومی `k2` را در کنار `k1` به جدول کلیدهای مجاز کلاینت‌ها اضافه کرده و نسخهٔ جدید اپ را منتشر کنید.
3. پس از انتشار نسخهٔ جدید، Secret مخزن (`RATES_SIGNING_KEY`) را به کلید خصوصی `k2` تغییر دهید و `kid` را روی `"k2"` تنظیم نمایید.

---

## ۳. مراحل انتشار نسخهٔ جدید (`Release Checklist`)

1. اطمینان از سبز بودن تمامی ورک‌فلوهای `check.yml`، `security.yml` و `codeql.yml` روی شاخهٔ `main`.
2. به‌روزرسانی شماره نسخه در `app/build.gradle.kts` و مستندات `README.md`.
3. ایجاد تگ `annotated` با توضیحات فارسی:
   ```bash
   git tag -a v1.2.0 -m "ژتون نسخه ۱.۲.۰"
   git push origin v1.2.0
   ```
4. هرگز تگ‌های منتشرشده را با `--force` جابه‌جا نکنید.
